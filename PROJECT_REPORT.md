# Mini-Courier Planner: DAA Capstone Report

## Problem Statement

A small courier operation must prioritize parcels, choose a load under a van weight limit, navigate a weighted road network, and plan a route visiting every delivery location before returning to its warehouse. The project demonstrates algorithmic solutions for these related but distinct tasks using a shared CSV dataset.

## Design

The application is divided into small modules under `src/`. `data_loader.py` validates and parses the parcel and route CSV files, creating an undirected adjacency-list graph. The algorithm modules accept in-memory parcel or graph structures and do not own data-file paths. `main.py` integrates these modules using the checked-in datasets. `performance.py` generates deterministic synthetic inputs and saves measured results under `images/`.

## Dataset and Methodology

The parcel CSV contains eight records with identifier, integer priority, integer weight, integer value, and delivery deadline. The route CSV contains eight undirected weighted edges connecting five locations. The van capacity used by the integrated demonstration is 8 kg. Merge Sort is used for descending priority; deadlines are displayed but do not affect that ordering or the value-maximizing packing objective. Knapsack is 0/1: a parcel cannot be split or selected more than once. Dijkstra runs from Warehouse. The delivery tour uses Nearest Neighbor and returns to its start when the selected route has a return edge.

The benchmark uses deterministic generated inputs, a fixed knapsack capacity of 50, and five runs per algorithm/size. It reports the median wall-clock duration. Graphs are connected by a chain, with additional random edges. Results are local measurements and should not be interpreted as hardware-independent performance claims.

## Algorithms

- **Merge Sort:** recursively partitions and merges parcels in descending priority order. Equal priorities preserve input order.
- **0/1 Knapsack:** dynamic programming tabulates the maximum value achievable for each prefix of parcels and capacity, then backtracks through the table to recover selected parcels.
- **Dijkstra:** a min-heap selects the next closest unprocessed location and relaxes outgoing edges. Negative weights are rejected.
- **Nearest Neighbor TSP:** repeatedly selects the closest unvisited adjacent location, then returns to the warehouse. This is a heuristic approximation, not necessarily the optimal tour; it fails explicitly when it cannot visit all locations or return.

## Complexity Analysis

For $n$ parcels, graph vertices $V$, edges $E$, and integer capacity $W$:

| Algorithm | Time complexity | Space complexity |
| --- | --- | --- |
| Merge Sort | $O(n \log n)$ | $O(n)$ |
| 0/1 Knapsack DP | $O(nW)$ | $O(nW)$ |
| Dijkstra (binary heap) | $O((V+E)\log V)$ | $O(V+E)$ |
| Nearest Neighbor TSP | $O(V^2)$ | $O(V)$ |

## Test Results

The project was verified with Python 3.13.14. `python -m unittest discover -s tests -v` completed successfully: 12 tests passed. Coverage includes the sorting order and stability, optimal knapsack value and capacity, invalid capacity/weights, shortest distance and path reconstruction, unreachable destinations, valid closed TSP tours, missing return edges, CSV row counts and undirected loading, missing files/columns, and malformed numeric fields.

The CSV loader completed successfully with 8 parcels and 5 locations. The integrated program selected parcels with total value 140 at 8 kg, found a 10 km shortest route from Warehouse to D, and produced a 22 km nearest-neighbor tour. These are outputs of the checked-in sample data, not claims of globally optimal TSP routing.

## Limitations

- Deadlines are stored and shown but are not used to schedule deliveries or alter parcel selection.
- The demonstration uses a fixed 8 kg van capacity; it is not currently a command-line setting.
- Knapsack DP is pseudo-polynomial in capacity and uses an $O(nW)$ table.
- Nearest Neighbor is order-dependent and can produce a suboptimal tour; it also requires an available return edge for the constructed final location.
- The benchmark uses synthetic graphs and parcels, a fixed capacity, and one machine. It is indicative, not a formal performance study.
- Distances are sample weights in kilometres and do not model traffic or time-dependent roads.

## Conclusion and Future Scope

The project integrates sorting, dynamic programming, graph shortest paths, and an approximate TSP tour with validated CSV input. The current sample run demonstrates feasible high-value packing and route calculation, and the test suite covers both normal and invalid-input cases. Future work could incorporate deadline-aware dispatch, capacity configuration, route optimization beyond a greedy heuristic, traffic/time constraints, and larger controlled benchmark datasets.
